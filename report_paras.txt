四、题目一：P0010  合并有序序列
4.1  题目简述
（用自己的话概括题目要求，100 字以内。不要照抄题面。）
输入一个整数 n，再输入两个各含 n 个整数的升序序列，要求用 O(n) 时间把两个序列合并成一个新的升序序列并输出。
4.2  算法思路
（不少于 200 字，须包含以下四部分。）
（1）问题分析：
题目本质是二路归并。输入两个长度均为 n 的非降序序列，需要输出长度为 2n 的合并结果。由于两个序列本身已经有序，每次只需比较两个序列当前剩余部分的首元素，把较小者放入结果，即可保证结果整体有序。每行整数不超过 100000 个，n 最大为 100000，因此必须在线性时间内完成，不能先把两个序列拼接起来再整体排序。
（2）算法选择：
选用双指针二路归并。指针 i 指向序列 a 的当前元素，指针 j 指向序列 b 的当前元素，result 保存结果。每轮比较 a[i] 与 b[j]，把较小者加入 result 并后移对应指针；当某一序列被取完后，把另一序列剩余部分一次性追加。选择该算法是因为两个序列本身有序，双指针每个元素只访问一次，时间严格为 O(n)，实现简单且稳定。
（3）正确性说明（若使用双指针或链表操作，须写明指针如何移动、为什么不会漏解）：
初始时 i=j=0，result 为空。两个子序列分别有序，所以每轮取两个剩余首元素中较小者加入 result，既能保证 result 末尾不大于新加入元素，也能保证不遗漏元素；被移动的指针不会回头，因此每个元素恰好被访问一次。当一方被取完后，另一方剩余部分仍保持升序且都大于 result 当前末尾，直接 extend 即可。最终 result 长度为 2n，包含全部输入元素。
（4）复杂度分析（时间复杂度、空间复杂度，并结合数据范围说明为何不会超时）：
时间复杂度 O(n)：每轮比较都会使 i 或 j 至少增加 1，两个序列共 2n 个元素，循环总次数不超过 2n。空间复杂度 O(n)：主要是保存结果的 result 列表，以及两个输入列表 a、b，均与 n 同阶。n 最大 100000，200000 次线性操作远小于 1 秒限制，不会超时。
（5）边界情况的考虑与处理：
主要考虑了以下边界：两个序列中出现相等元素时，用 a[i] <= b[j] 优先取 a，保证相等元素也能稳定进入结果；某一序列先被取完后，剩余部分用切片一次性 extend，并用 i < n and j < n 防止下标越界；读入为空时直接 return，避免访问 data[0] 出错。

五、题目二：P0030  约瑟夫问题
5.1  题目简述
（用自己的话概括题目要求，100 字以内。不要照抄题面。）
输入若干行，每行给出 n 和 m，表示 n 只猴子从 1 号起顺时针报数，数到 m 的出圈，求最后剩下的猴王编号；以一行 0 0 表示结束，每组输出一行。
5.2  算法思路
（不少于 200 字，须包含以下四部分。）
（1）问题分析：
这是约瑟夫环问题。给定 n 和 m，每轮删除当前环中的第 m 个元素，删除 n-1 次后只剩一个元素，要求输出它的原始编号。输入含多组数据，以 n=m=0 结束，且 0<n,m<=300。虽然 n 不大，但题目要求思路清晰，采用递推公式可以在 O(n) 时间内直接计算每一组答案。
（2）算法选择：
采用约瑟夫问题的逆推公式。设 f(i) 表示 i 个人报数到 m 出列时，最后幸存者在从 0 开始编号的环中的位置，则 f(1)=0，f(i)=(f(i-1)+m) % i。循环从 i=2 递推到 i=n，得到 f(n) 后加 1 还原为从 1 开始的编号。选择递推而不是模拟删除，是因为递推每组只需 O(n) 时间和 O(1) 额外空间，代码简洁，也不易在报数边界处出错。
（3）正确性说明（若使用双指针或链表操作，须写明指针如何移动、为什么不会漏解）：
递推的含义是：f(i-1) 是 i-1 个人时的幸存者位置；当人数从 i-1 增加到 i 时，可以看作上一次删除后从被删位置的下一位重新编号为 0，幸存者在新的 0 号坐标系中位置为 f(i-1)，把它映射回 i 个人的 0 号坐标系需要加上 m 并取模 i，即 (f(i-1)+m) % i。因此由 f(1)=0 递推到 n 即得 0 号坐标系下的幸存者编号，再加 1 得到题目要求的 1 号起点编号。
（4）复杂度分析（时间复杂度、空间复杂度，并结合数据范围说明为何不会超时）：
时间复杂度 O(n)：每组数据循环 2 到 n 共 n-1 次常数运算；若有 k 组数据，总时间为 O(k·n)。空间复杂度 O(1)：递推只使用 s、i 两个变量；results 列表用于保存各组输出，是必要的输出存储。n,m 最大 300，任何一组都能在极短时间内完成，不会超时。
（5）边界情况的考虑与处理：
主要考虑了：m 大于当前人数时取模运算使报数自然在环内循环，不会越界；n=1 时 for 循环不执行，直接返回 s+1=1；输入中出现空行时用 if not line.strip(): continue 跳过；以 0 0 作为结束标记，先判断结束再处理，避免把 0 0 当作一组数据。

六、题目三：P0050  寻找链表交叉点
6.1  题目简述
（用自己的话概括题目要求，100 字以内。不要照抄题面。）
给定两个单链表 a 和 b，程序先把 a 的尾结点连接到 b 的第 n 个结点，使两条链表形成 Y 形；要求补全 findJointPoint 函数，在线性时间内返回二者共享的第一个结点的数据。
6.2  算法思路
（不少于 200 字，须包含以下四部分。）
（1）问题分析：
题目已经给出 Node、LinkList 与 genLinkList 框架。genLinkList 读入两个序列并令 a 的尾结点 next 指向 b 的第 n 个结点，使 a 和 b 共享从 b 的第 n 个结点开始的后缀。findJointPoint 需要返回分叉点。由于分叉点之后两条链表完全相同，从两个头结点到分叉点的路径长度不同，但共享后缀长度相同。
（2）算法选择：
采用长度对齐的双指针法。先分别遍历 a、b 求出长度 len_a、len_b；然后让较长链表的指针先走长度差 |len_a-len_b| 步，使两个指针到分叉点的剩余距离相等；之后两个指针同步前进，第一次指向同一结点即为共享首结点。选择该算法是因为它只用常数空间，总遍历次数为 O(len_a+len_b)，满足题目 O(n) 要求。
（3）正确性说明（若使用双指针或链表操作，须写明指针如何移动、为什么不会漏解）：
设 a 的独占前缀长为 x，b 的独占前缀长为 y，共享后缀长为 z，则 len_a=x+z，len_b=y+z。较长的链表先走 |x-y| 步后，两个指针分别位于从各自头结点出发、到分叉点距离相同的位置；同步移动时，若尚未相遇则两指针不可能指向同一结点，因此可以安全地同时后移，不会跳过交点；到达分叉点时两者必然同时指向同一结点，循环结束，返回 pa.data。
（4）复杂度分析（时间复杂度、空间复杂度，并结合数据范围说明为何不会超时）：
时间复杂度 O(n)：先遍历求两个链表长度共 O(len_a+len_b)，再移动指针至相遇最多 O(len_a+len_b)，整体为线性。空间复杂度 O(1)：只使用 pa、pb 和两个长度变量等常数空间。两个链表总长度最多 200000，线性操作可在 1 秒内完成，不会超时。
（5）边界情况的考虑与处理：
考虑了以下边界：len_a 与 len_b 相等时不跳过、直接同步扫描；分叉点为 b 的第一个结点（n=1）时，a 先走完独占前缀后与 pb 在 b.head 相遇；分叉点位于链表末尾时共享后缀只有一个结点，while pa is not pb 同样能正确返回。题目保证一定相交，因此未对 pa 为 None 做额外处理。
